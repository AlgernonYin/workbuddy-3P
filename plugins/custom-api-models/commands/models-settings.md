---
description: Open the WorkBuddy 3P settings panel or a host question-tool wizard
---

Use `models_settings` with `action: status` to open the native MCP Apps settings panel. Tell the user this panel adjusts third-party model defaults in the current cloud sandbox, not the account or native global settings. Do not ask them to write JSON or shell commands.

Offer parameter priority as `3p` (default) or `native`. Resolve it in this order: saved `workbuddy-3p.parameters.json` > `WB3P_PARAMETER_PRIORITY` > default `3p`. Do not add a hidden CLI default or mix another fallback. `3p` keeps third-party requests on the 3P parameter policy and its self-running loopback adaptation inside the target cloud host; `native` uses native direct connection and turns off 3P forced parameters. `state.parameterPriority` defaults to `3p` when absent. Apply `patch.parameterPriority` only when the user changes it. In `official` mode, the plugin rejects proxy forwarding and sends no third-party traffic; this setting does not create a third-party route.

If the host does not render the native panel, call `models_settings` with `action: panel` and pass ONLY its `artifactPath` to the host's `present_files` tool. That standalone HTML is a visual draft editor: it cannot directly write files. Its generated secret-free instruction must be sent to the ORIGINAL chat to apply. Do not describe preview or clipboard success as saved settings.

If HTML preview is unavailable, or the host does not render MCP Apps, use the host's interactive question tool (e.g. `AskUserQuestion`) to offer: parameter priority (3P / native); thinking strength/context; providers/custom routes; official/third-party source. Read the live status, offer only that model's declared supportedEfforts and protocol fields, and validate the requested input context against baseInputTokens. Unknown models must not receive fabricated parameters. Context is only a local host input limit; it cannot increase upstream capacity, and it is not evidence that context compression works. Do not infer adjustable effort from `onlyReasoning`: a forced-thinking model can still expose `low/high/max`. Offer adjustments only from live `supportedEfforts` and `canDisableThinking`/protocol declarations. Unsupported native thinking toggles must not be offered.

For "highest for every model", call status again then apply `{maxEffort:true}` using that fresh revision; do not set every model to the literal `max`. For individual changes, apply only the selected fields. Keep credentials when editing labels/routes. The shared Node loopback proxy auto-starts/stops inside the target cloud sandbox. The host caller uses an opaque proxy key; the proxy reads its private mode-600 state cache, selects the original upstream key, and uses that key only on the upstream Authorization request. It does not return or display the upstream key in the UI/session. Native priority uses a native direct connection. If an older host cache still points at the loopback, the proxy returns HTTP 410 and the user must reselect the model; do not transparently pass it through, because that would leave credential-forwarding semantics ambiguous. Official mode rejects the route. A changed endpoint requires an explicit new `apiKeyEnv` reference or user consent to `reuseCredential:true`. Never ask for keys in chat, read secrets into the model context, or return inline keys. Use private runtime credential files/environment/account-private profile for credentials.

Before applying a draft, match the intended changes against the user's request. If revision is stale, reopen status and show differences before constructing a new patch; never silently replace its revision. After success state that private backups exist and host model-catalog refresh/reselection may still be required. `runtimeVerified:false` is disk state only; a saved configuration is not HTTP success. Do not claim physical-phone acceptance or verified context compression from this flow. Never claim new sandboxes inherit local changes; private profile must be separately updated/uploaded by its owner.
