Read `../../commands/models-settings.md` and follow its workflow. Prefer the native `models_settings` MCP Apps panel; when the host does not render MCP Apps, use the tested host question-tool wizard such as `AskUserQuestion`. Do not modify webpage code, native global/session settings, or unrelated services. Before applying, reread the settings revision, validate model capabilities, and change only the user-requested scope. Offer parameter priority `3p` (default) or `native`; resolve file > `WB3P_PARAMETER_PRIORITY` > default `3p` and send `patch.parameterPriority` only when changed. Native uses native direct connection; 3P uses the target-cloud-host loopback adapter. Official mode rejects proxy forwarding and has no third-party traffic. An older cached proxy binding returns HTTP 410 and requires model reselection; do not transparently pass it through. The shared Node loopback daemon auto-starts/stops in the target cloud sandbox, not on the assistant computer or client device. The host caller uses an opaque proxy key; the proxy reads its private mode-600 state cache and uses the original upstream key only on the upstream Authorization request, without returning it to the caller/UI/session. Keep the private state/runtime files gitignored. Validate adjustments from live `supportedEfforts` and `canDisableThinking`; do not infer them from `onlyReasoning`. Provider credentials remain private in the runtime/account profile. A standalone HTML preview is only a draft, not a successful application. Do not claim HTTP success, physical-phone acceptance or verified context compression from a saved/draft state.
