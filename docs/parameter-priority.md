# 参数优先级与宿主自运行回环（2.5.0）

本文定义 WorkBuddy 3P 2.5.0 的 `parameterPriority` 契约与运行边界。它描述配置和接口，不是 HTTP 运行验收报告。

## 解析顺序

有效参数优先级按以下顺序解析：

1. 已保存的 `workbuddy-3p.parameters.json`（`version: 1`、`priority`）
2. 环境变量 `WB3P_PARAMETER_PRIORITY`
3. 默认值 `3p`

MCP、命令和 UI 不注入隐藏的 CLI 默认值，也不把另一套默认混入解析链。未显式修改时，读取上述结果；只有用户更改后才提交对应字段。

设置面板接口保持不变，只新增：

- `state.parameterPriority: "3p" | "native"`，缺失时按 `3p` 展示。
- `patch.parameterPriority: "3p" | "native"`，仅在变更时需要提交。

`action`、`expectedRevision`、commit 回执、revision guard、备份/回滚和密钥保护逻辑不变。

## 两种优先模式

### `3p`（默认）

第三方请求按 3P 的模型能力与协议声明处理参数。目标云端宿主内的 Node 回环适配器负责强制已声明的思考参数，并可作为第三方请求的本地转发目标。

### `native`

第三方模型走原生直连，关闭 3P 强制参数。宿主原生能力、会话/用户覆盖和直连行为优先。

如果宿主缓存仍保留旧的回环代理绑定，代理返回 HTTP 410，用户必须重选模型后再使用原生直连。这里不做透明透传，避免在 native 模式下留下含义不清的凭据转发路径。

### `official`

`official` 模式拒绝代理转发，不建立第三方请求路径。参数优先级偏好可以保留为配置，但不会因此产生第三方流量；切回 `3p` 或 `native` 的第三方模式后，是否使用回环仍按当时的解析结果和目标云端运行状态决定。

## 目标云端宿主与回环边界

- 文档中的“本机 / localhost / 回环”只指插件所在的目标云端沙箱，不是助手运行的 Windows 电脑，也不是网页或手机客户端。
- Node 回环代理自动启动、自动停止，并以共享守护进程方式服务同一目标云端沙箱内的多个 MCP 会话；它不是助手侧常驻服务，也不是浏览器扩展。
- 宿主调用端只使用不透明代理 key 访问回环。回环代理从插件私有、权限为 `600` 且已加入 `.gitignore` 的 state/runtime 缓存中读取原上游 key，并仅在向上游发出的 Authorization 请求中使用；不会把原 key 返回给调用端、UI 或会话，也不会进入公开仓库。
- 目标云端宿主停止、切换 `official` 或最新绑定校验失败时，代理路由必须拒绝；不能依赖旧缓存建立第三方通道。

## 参数能力约束

| 能力项 | `3p` 回环 | `native` 直连 |
| --- | --- | --- |
| 模型档位来源 | live `supportedEfforts` / 协议声明 | 宿主原生能力与声明 |
| DeepSeek V4.1 Flash `off` | 可按声明由代理强制 | 2.4 native 限制下禁用 |
| Kimi K3 `off` | 可按声明由代理强制 | 2.4 native 限制下禁用 |
| 未知模型参数 | 不伪造 | 不伪造 |
| 输入窗口 | 宿主本地输入上限 | 宿主本地输入上限 |

- 思考档位只按 live `supportedEfforts`、`canDisableThinking` 和协议字段下发。不要用 `onlyReasoning` 推断是否存在档位；强制思考模型仍可能提供 `low/high/max`。未知模型不伪造 `reasoning_effort`、`enable_thinking`、`thinking` 或 token 预算参数。
- `native` 关闭 3P 强制参数，不代表可以替未知模型猜测原生参数。
- 在 `3p` 回环适配下，DeepSeek V4.1 Flash 与 Kimi K3 的 `off` 可由代理按最新模型能力声明强制；2.4 的 native `off` 限制仅适用于 native 路径。并非所有模型都支持 `off`，仍只下发已声明的能力。
- 输入窗口是宿主本地输入上限的元数据调整，不能扩大上游模型容量，也不等于上下文压缩策略已通过这些元数据生效。
- 配置保存、面板回执、文件落盘和 `runtimeVerified:false` 只表示配置状态，不等于真实 HTTP 请求成功，也不等于期望参数已被上游采用。

## 入口与验证边界

- 宿主原生渲染 MCP Apps 时优先使用设置面板；宿主不渲染时，可用已实测入口流程中的 `AskUserQuestion` 等 question-tool 向导读取状态并生成显式 patch。
- 独立的 UI 回归只使用 fake state，覆盖默认 `3p`、变更时才提交 `parameterPriority`、标签和移动端无横向溢出；不发送网络请求，不启动真实代理，不接触密钥。
- 真实 proxy 启停、共享守护、native 旧缓存 HTTP 410/重选、official 拒绝以及 HTTP 参数行为仍需目标云端宿主的独立运行验收。
- 本文不宣称真实手机验收通过，也不宣称上下文压缩通过。

## 生命周期与限制

适配器只监听 `127.0.0.1` 的随机端口。同一配置目录的 SessionStart/CLI/MCP 启动会用健康 HMAC 复用同一进程；每个活动 MCP 每 45 秒检查一次，异常退出会尝试恢复。无活动 MCP 或请求时，闲置 30 分钟退出。退出只移除自己的运行时登记，保留旧回环 URI 与 opaque token：3p 失效时拒绝请求，绝不静默降为供应商直连。只有已提交的 native/official 路由事务才会切换路径。强制杀进程、平台睡眠或回收无法保证立即恢复；下次同步会重建绑定，宿主可能仍需刷新并重选模型。

每个请求默认最长 10 分钟，可在目标宿主通过 `WB3P_PARAMETER_TIMEOUT_MS` 设置为 1000–1800000 毫秒；最多 4 个并发请求、单请求 16 MiB、共同缓冲预算 32 MiB。流式响应使用 backpressure，客户端中断会取消上游请求。禁止跟随重定向，不转发宿主 Cookie 或其它认证头。上游错误正文不会回显，以免第三方服务把密钥/内部数据夹带在错误里。

设置影响新取得的路由快照；切换前已经开始的上游请求可能继续完成，不能把模式切换宣称为撤销已经发送的数据。回环不是对同一宿主 root/同用户恶意进程的隔离边界。私有 state/runtime/备份必须留在受保护的配置目录内。
